# PSC

PSC is a single-file compiler and semantic development environment for typed PowerShell/SM source. It emits deterministic managed assemblies without an SMA runtime dependency for admitted code, links native Windows PE images, and directly emits verified x64 ELF leaf libraries. No SDK or project file is needed for managed compilation.

**Start here:** PowerShell 7.7 / .NET 11, Git, and `PSC.ps1`. `Invoke-PSC.ps1` is the legacy entry point.

```powershell
$api = & ./PSC.ps1                       # Describe PSC, without compiling
$api.Describe('Compile').Parameters       # Live command contract
$dev = $api.OpenDevelopment('./psc-tree') # Project the canonical source
& ./PSC.ps1 -SourcePath ./psc-tree/SM/Calibration.sexe -Program -OutputPath ./Calibration.dll
```

`Calibration.dll` is a managed program, not a native executable. The embedded SM fixture exercises its entry point. `-Native` adds the existing Windows NativeAOT/COFF pipeline; `NativeCil` is the separate, currently leaf-only native path.

## Type system and realization contract

PSC owns first-class typed representations of the ScriptType System (STS) and the Common Type System (CTS). STS supports independently acquired structural contracts, identity, composition, binding, refinement and realization; CTS preserves faithful CLI interoperability. Semantic analysis must not require runtime materialization. Mappings between STS and CTS are explicit, typed and reversible where representable. SMA is the authoring and source-evidence substrate. Managed CLI, NativeAOT and independent native ISA are supported realization paths; neither CLR nor the C runtime is intrinsic to STS. Independent native realization shall support explicit static, dynamic or absent C runtime linkage. Source, semantic and realization retention are explicit artifact requirements, independent of execution dependencies.

This is the architectural mission, not a claim of completed implementation. Reconcile ScriptType, compiler binding and native IR before adding competing representations. Keep the existing NativeAOT path for Notepad and PSNES. Distinguish source evidence from semantic definitions; keep runtime reflection and synthetic execution representations out of semantic authority.

## Reflective managed runspace

`ScriptTypeReflection.InvokeBound(role, binding, arguments)` consumes an exact locally declared `ScriptTypeBinding` with its original member reference, checks the role's realized contract, acquires the provider and dependency leases, and invokes the selected compiled target without a second name or overload search. It refuses unmaterialized signatures, nonexact argument representations, unrelated contract/member identities and unavailable realizations. The current profile does not yet admit inherited bindings, conversion plans or symbolic argument storage. `HandleTable` uses CoreLib collections for allocation, ownership traversal and deferred reclamation. `HandleCollector.Collect(table)` owns eligible cleanup execution, completion and free-slot recycling, using the existing table gate and storage. HandleTable owns eligibility, leases and dependency edges and calls the collector when lifetime operations release work. Both are realized in HandleTable.dll because the current synchronous lifetime contract is mutually dependent; no independent collector assembly or tracing GC is claimed. A bounded standalone CoreCLR control has exercised runtime definition construction, binding, replacement and withdrawal using only CoreLib and compiled PSC assemblies. Generated-thunk names encode the case-normalized member name and length-framed parameter identities as strict UTF-8 hexadecimal identifiers rather than cryptographic digests. HandleTable, DiscoveryMechanisms and ScriptType have no framework assembly reference beyond CoreLib; the standalone CoreCLR control also exercises generated-thunk binding, invocation and withdrawal. Rebuild previously generated thunk assemblies to match the new naming scheme. The names are longer than the former fixed-size digest names. The target is a lowered reflective runspace that parses `.ps1` without the SMA assembly, using acquired PowerShell language semantics rather than a second grammar. Independent parser realization is not implemented; current PSC authoring and compilation still acquire source using SMA.

HandleTable's internal lookup, pinning, retention, name resolution and ownership traversal operations now take an explicit typed table participant. Fourteen additional public operations (including collection, withdrawal, succession, retention, pair leasing and rebinding) now require an explicit HandleTable participant. Register, Open, Close and Revoke also take an explicit table participant. The authoring-side query lease acquires exact CLR operation signatures once from the loaded faculty; compiled consumers use typed static calls. The existing IDisposable and cursor instance entry points remain compatibility boundaries. Lease and retention records use explicit typed Create operations; the fence Completed and Signal operations take an explicit fence participant. Rebuild callers of the changed operations. `ScriptTypeBindingExtension.SelectBound(extension, candidates, arguments)` is a static operation with an explicit extension participant; rebuild consumers of the previous instance signature. The existing selector memo and lease semantics are retained.

ScriptTypeContract reflection and binding operations now take an explicit contract participant. Rebuild callers of the previous instance signatures; the binding still retains the original owner, member and argument references.

ScriptTypeRealization binding, candidate lookup and operation lookup take an explicit realization participant. ScriptTypeBinding, ScriptTypeCall and ScriptTypeRole use typed Create operations rather than implicit receiver constructors. Rebuild callers of the changed signatures.

ScriptTypeSmaSelector now takes an explicit adapter participant. A closed delegate binds that participant to the static selection method without changing the binding extension contract. The canonical ScriptType faculty contains no implicit receiver references.

DiscoveryMechanisms uses explicit typed record creation for clean references, predictive scalars and when clauses. InquiryCase.Find(case, axis) retains reference-identity lookup and first matching reading selection. Rebuild callers of the previous constructors and Find instance signature.

## Advisory redundancy analysis

Use the existing graph to compare authored function and method bodies, including their source identities and locations:

```powershell
$graph = & ./PSC.ps1 -Mode Graph -ProjectPath .
$report = $graph.Redundancy()
$report.Findings
$graph.Redundancy('Select-PscStructuralNumericOverload', 3, 10)
```

Identical body tokens use the retained SMA token stream and ignore comments and horizontal trivia but preserve token spellings and newlines. Shared call evidence distinguishes bound targets from unresolved spellings; overlap is intersection divided by union. Findings are investigative, not proof of equivalent signatures, behavior or unnecessary duplication. Embedded and parse-incomplete declarations are excluded and counted. No Guard admission rule is changed; inspect target-specific and independent test implementations before consolidation. Reproduce with the projected `Tests/Test-Redundancy.ps1 -Compiler ./PSC.ps1`; this supplementary fixture is not a mandatory baseline stage.

## Source formats

| Extension | Role | Analogue | Intent |
|---|---|---|---|
| .sm1 | Script | .ps1 | Independent executable source |
| .srm1 | Script Resource Module | .psm1 | Reusable behavior, contracts, types and resources |
| .sexe | Script Executable | .exe | One-shot executable appliance before realization |

The extension describes intent, not executable eligibility. PSC is the realization authority; stock `pwsh` execution is not a requirement. Direct SMA-free one-shot launch through PSC is a target, not an implemented feature. `Run` currently executes through SMA as a reference path.

## Find, inspect, edit, conform

`-h` / `-Help` exposes the development entry points before the full command help. The default API provides the live mode inventory (`Modes`), `Describe()`, `Guide()`, `OpenDevelopment()`, `OpenSemanticIndex()`, `OpenDocument()`, `Find()` and `Search()`. Document queries retain the current parsed revision when it has no explicit parser dependencies; documents with using statements or script requirements are conservatively reparsed. Use `LineCount()`, `LineStart(line)` and `GetText(offset,length)` for source coordinates (one-based line, UTF-16 offset). `DeclarationAt(line,column)` acquires the smallest containing supported declaration as an editable revision-bound reference; use `Replace()`, `Undo()`, `Redo()` and `Save()` on that document. `Parses()` exposes actual document parse attempts. A changed revision is parsed before use; successful replacement retains its admitted AST when eligible. This does not yet eliminate repeated visitor traversal or provide incremental cross-document binding.

The canonical source is `PSC.ps1`. The worktree is a disposable, ordered AST projection, including embedded SM sources and tests. Do not maintain a competing source tree.

| Tool | Responsibility |
|---|---|
| `git grep -n -F -- 'ConvertTo-PscIr' PSC.ps1` | Literal text in tracked source |
| `rg -n -F -- 'Apply' ./psc-tree` | Literal text in the projected worktree |
| `$api.Find('ConvertTo-PscIr')` | Named AST declarations |
| `$api.Search('PersistedAssemblyBuilder')` | AST declaration extents containing literal text |
| `git log -p -- PSC.ps1` | Committed history |

```powershell
$q = $api.Find('ConvertTo-PscIr')
try { $q.Pull(10); $q.Coverage() } finally { $q.Dispose() }
$api.Describe('Guard').DispatchExtent.Text
$api.Guide()
```

Query returns typed references with source identity, owner, extent and coverage. Pull in windows of 1..256; dispose cursors. Literal containment includes comments and strings inside a declaration, not proof of binding. Use `$dev.Find('Apply')` or `$dev.Search('literal')` to include projected resources; canonical queries do not parse embedded source strings. `OpenQuery` supports explicit paths, owner, kind and limit, including non-loading CIL inspection for binary queries.

A retained semantic index is opened with `$index = $api.OpenSemanticIndex($root)`; `$graph = $index.Refresh()` uses the existing SMA graph and retains parsed root source by path and exact byte digest when it has no explicit parser-dependency markers. Sources with parse errors, `using` statements or script requirements are conservatively reparsed. `SourceRevision`, `SourcesParsed`, `SourcesReused` and `SourcesRemoved` describe each refresh. Declarations, edges, embedded source and lint are rebuilt and rebound, not incrementally cached; refresh is not an atomic filesystem snapshot; cross-file and overload binding remain limited. The index is in-process, not an on-disk database. Graph method binding is confined to the same parsed source identity, including independent embedded literals. `$graph.Changes()` uses the pinned compiler source inventory without rebuilding graph facts.

A read-only query reference can become an edit reference only through exact source/extent validation (`$doc.Resolve($hit)`). A document's own `Find` returns revision-bound editable references directly. Example, using a behavior-preserving numeric-literal edit in the projected calibration resource:

```powershell
$doc = $dev.OpenDocument('SM/Calibration.sm1')
$hit = $doc.Find('Declaration','Apply','SmCalibrationProvider',1)[0]
$doc.Replace($hit, $hit.Target.Extent.Text.Replace('4.0 + 1.25','4.0 + 1.250'))
$doc.Undo()
$doc.Redo()
$doc.Save()
$dev.Changes()
$dev.Affected()
$dev.Collate('./PSC.next.ps1')
$result = $dev.Conform($true)
$result.Stages | Select-Object Name,State,ExitCode
```

External edits to projected files are also supported. Start with a clean Git baseline and a new or matching projection. Collate needs a fresh candidate destination and rejects missing/untracked units and changed declaration boundaries. Additions, deletions and renames still require explicit canonical edits. Affected reports declared faculty dependencies, not exhaustive semantic or test coverage. No tests are omitted based on Affected.

**Strict authoring admission (migration in progress):** PSC and its embedded source modules, including the checker, are held to zero current lint findings. Guard no longer grants exemptions for findings in committed source. Lint reports implicit receivers, authored scriptblock expressions, explicit scriptblock type references (including nested array/generic references) and executable AST materialization. Parser-owned declaration roots are source evidence, not authored expressions. Compile remains a separate SMA compatibility boundary. The current source intentionally fails Guard during migration; no claim of acceptance or full conformance is made. Existing historical test modules are retained as evidence, including former grandfathering expectations that conflict with the new rule. Continue independent tests without treating them as admission. New source edits use PSC's revision-bound document API. The module activation and native semantic control requirements are in AGENTS.md; they are not yet implemented.

Conform streams child stdout and stderr to the invoking host as they become available, with stage names, paths and completion status; the typed receipt retains each decoded stream separately. Cross-stream display order is not a guaranteed chronological ordering. Conform runs Guard against committed source, the candidate API and projection, then literal regression resources obtained from the same committed baseline without candidate execution. If the embedded resource inventory changes, supplementary candidate regression stages also run. Standalone and candidate Guard consume byte-verified committed source directly, without staging a temporary Git repository. Both record the candidate digest and, when present, the committed path, commit, blob identity and digest. Conform reuses that same committed object. A standalone file without a committed baseline is held to zero findings and an empty verification inventory; failed reads of existing objects are not treated as absence. Guard parses decoded source without line joining; only protected extent comparison normalizes line endings. Unborn Git repositories require Git support for show-ref --exists. The report identifies the runner and resource digests. Required stages are declared before execution, with exact names, provenance, source identity and permitted states; VerifyStages checks the observations against those requirements; VerifyScope independently requires the ordered mandatory compiler and fixture stages, resource inventory identities and permitted Verify outcome. VerifyConformance re-extracts both resource inventories from the retained committed bytes and the identified candidate, comparing independent baseline and runner digest pins. Conform also pins the observed absolute PowerShell executable path and file digest before launch and after every executed stage. Executed stages carry that identity; skipped stages do not. Supply -ExpectedHostSha256 to Conform or VerifyConformance to check an independently retained executable digest. Legacy scope reports may lack host evidence and cannot satisfy an independent host pin. Conform additionally inventories ten fixed files in the colocated PowerShell distribution (entry assembly, deps/runtimeconfig, ConsoleHost, SMA, CoreLib, CoreCLR, JIT, hostfxr and hostpolicy), checks their bytes before and after each executed stage and at completion, and records the ordered inventory digest in executed stages. VerifyConformance checks the recorded inventory structure and stage identities; -ExpectedRuntimeSha256 independently pins that digest. Legacy reports cannot satisfy this independent pin without runtime evidence. This is a bounded file inventory, not an observation of child module loads, complete runtime dependency closure or process authentication; non-colocated hosts are not admitted. Roadmap checks retained inputs when present; legacy reports without retained bytes remain scope-only observations. Primary fixture stages use baseline resources, and Candidate/ stages identify supplementary tests. Candidate resource extraction is checked against the Guard digest; the candidate and complete runner identities are checked before and after each stage. This detects persistent interstage changes, not changes made and restored within one child process. Guard and Conform resolve one absolute Git executable through application-only discovery, pin its SHA-256 before and after every committed-source read, and retain its path and digest. Supply -ExpectedGitSha256 to Guard, Conform or VerifyConformance to compare an independently retained executable digest; legacy reports without Git evidence cannot satisfy that pin. This does not authenticate Git, pin its libraries or helpers, or constrain Git invocations inside candidate fixtures. Standalone replacement-reference checks use the same native read boundary as committed-object acquisition. The byte-level blob identity calculation follows Pwsh prior art. Report consistency does not authenticate the runner or its evidence. This is not full assessment-authority closure: the caller must choose a trusted runner, and historical Verify still executes candidate code. `true` selects development scope and skips historical Windows verification (`Complete = False`); `false` requests the full suite and requires its native toolchain. Review the result before explicitly promoting the candidate. Use `git diff -- PSC.ps1`, commit the reviewed change, verify HEAD, then open a fresh projection. Never silently change protected checkers. See [AGENTS.md](AGENTS.md) for engineering requirements.

## Compiler and runtime

- **Managed:** SMA AST and typed expression lowering, deterministic IL emission, static graph/data realization, reachability and fixed-parameter specialization.
- **Native:** pinned Windows NativeAOT compiler plus PSC COFF linker; direct CIL-to-IR-to-x64 ELF leaf emission and decoded-byte ABI checks. The direct backend does not yet replace ILC for general programs.
- **Faculties:** `HandleTable`, `DiscoveryMechanisms`, `ScriptType`, `PrimitiveConversion`, `ObjectDispatch`, `NativeEncoding`, `ElfEncoding`. Build with `-Mode BuildRuntime`. All seven faculties lower selected original declarations from the retained module inventory, including nested declaration scopes. Explicit dependency realizations map to their source definitions for signature binding. For admitted exact and closed numeric bindings, persisted dependency methods and explicit constructors select their original STS member first, then match the exact CLR realization by parameter and result references. Ambiguity and realization mismatch are refused; unsupported binding profiles still use the existing CLR compatibility path. BuildRuntime resolves the declared dependency order and builds all faculties in one isolated coordinator with one retained source acquisition, keeping faculty assembly identities out of the caller. Within that coordinator, dependency signature binding consumes the original contracts retained from preceding faculty builds; independent BuildFaculty calls acquire contracts for their own source scope. `BuildRuntime -CompilerRuntimeDirectory <bootstrap> -RuntimeDirectory <empty-output>` admits the existing no-contract compiler realization, composes the original resident dependency scopes without merging their descriptors, and rebuilds all eight artifacts in a separate directory. It refuses missing or incompatible admission receipts, nonempty output directories and external contract inputs. The coordinator acquires its declaration inventory once, uses retained persisted dependency witnesses, retires completed graph scopes outside the remaining transitive dependency closure in reverse order, and closes the admitted session. Selected lowering scopes do not replace the complete source scope. The lowerer returns its exact completed selection to the coordinator, and dependent function scopes are retained by their resolving source context. CLR compatibility projections have their own namespace; emitted types keep their original names and the compiler retains source names in its declaration scope. BuildRuntime without contract inputs also builds the compiler-private `compiler/CompilerDeclarations.dll` and writes a version 2 local selection receipt for it and HandleTable, ScriptType and PrimitiveConversion. The seven public faculty files and their dependency closure are unchanged. The compiled selection path verifies source, CoreLib, SMA, the existing TypeConverter framework dependency and all four admitted assembly digests once, loads the exact bytes in a private collectible context, and invokes typed delegates. Version 1 receipts require rebuilding. Missing or incompatible receipts refuse that path; no implicit interpreted fallback is permitted after selection is requested. Without an explicit directory the authoring selector is unchanged. The receipt identifies a trusted local build; it is not a signature or independent admission proof. This is explicit compiler self-consumption, not full startup activation. `PscApi.AcquireSelection(api,directory)` acquires an explicit resident selection session from the API source revision. `PscRuntimeSelection.Select(session,signatures,sources)` reuses the admitted selector without reading artifacts again; `Close(session)` withdraws it and requests context unloading. Resident structural specialization accepts the same session as `-RuntimeSelection`, and does not close a caller-owned session. CLI Compile with an explicit `-RuntimeDirectory` uses `Invoke-PscCompile` to acquire one session before lowering, supply it to both structural specialization and ordinary managed lowering (including the managed precursor of Native), and close it in a finally boundary before returning the managed result. The session remains inside the authoring operation, not the process dispatcher. Even an exact-only compilation refuses a missing or incompatible receipt when explicitly requested. Without an explicit directory CLI Compile retains interpreted selection. The retained session may also be supplied to `Export-LoweredAssembly -RuntimeSelection`: ordinary source static/instance calls and explicit constructors use session-owned compiled STS exact and numeric binding and retain the original CLR projection witnesses. Method closure, initializer lowering and recursive function-output inference use the same session; by default a selected compilation owns fresh declaration scopes, including their existing inference caches. `Export-LoweredAssembly -SourceAst <original-root> -RuntimeSelection <session> -RetainedScope <scope>` instead borrows a live resident source graph with a temporary CLR compatibility projection. The original AST, ordered class and enum selection, session and dependency scope must match exactly; acquire any rewritten record source before borrowing. The graph remains caller-owned on success or failure; `RealizedScope` ownership transfer is not admitted with `RetainedScope`. Synthetic function scopes acquire temporary graphs by default. For repeated program compilation, acquire the existing program function class with `Get-ScriptFunctionClass -Root <original-root> -Program`, then `Get-DeclarationScope -Root <function-class-parent-root> -Resolving <source-scope> -RuntimeSelection <session>`. Supply that dependent scope as `-RetainedFunctionScope` together with `-RetainedScope` and `-Program`. Both graphs remain caller-owned and acquire no replacement graphs; the dependent CLR projection resolves against the fresh source CLR projection. Explicit reprojection may substitute only a live projection of the identical direct dependency graph. Function provenance is retained with the scope, independent of active synthetic class caches. Ordinary lowering resolves function source, class and program entry from its selected declarations; borrowed compilation uses the retained referents without reading or displacing the acquisition dictionaries. External acquisition and inference retain identity-keyed conditional weak indexes. Live source or synthetic AST referents preserve their relationships, including null cache entries and parameterless program entries, but the indexes do not own abandoned source or synthetic ASTs. Retained scopes continue to own their declaration evidence and graph withdrawal remains explicit. The resolving source may be any live projection of the identical source graph. Function inference remains projection-local; withdraw the dependent graph before its source graph. Ordinary resident lowering tracks every graph it acquires, including incomplete projections; it withdraws temporary scopes in reverse acquisition order and removes their cache entries on success or failure. An explicit successful RealizedScope handoff retains only the selected graph; caller-owned dependency and declaration scopes are not withdrawn. CLR compatibility projections are collectible. `Get-DeclarationScope -Root <original-root> -RuntimeSelection <session> -RealizationOf <scope>` creates a separate compatibility projection from a live retained graph, including the original enum selection and dependencies; it neither replaces the root cache nor acquires another STS graph. Existing callers may retain prior CLR witnesses, which become eligible for reclamation when no longer referenced. Graph withdrawal remains independent of these witnesses. `PscScriptTypeAcquisition` constructs descriptors directly from the original SMA AST declarations in the selected execution domain. A resident scope stores only its owning session, scope and source coordinates, and CLR projection witnesses; it does not construct an interpreted descriptor graph. The compiled graph retains original imported referents and supplies typed acquisition, projection and binding results across the delegate boundary, with refusal status and diagnostic text instead of collectible exceptions. The authoring caller checks the selected member against its CLR realization. Graph scopes may be withdrawn individually through `PscRuntimeSelection.ReleaseGraph`; live importing scopes prevent withdrawal, and retired coordinates are never reused. Previously cached scope witnesses refuse subsequent operations rather than silently reacquiring a different semantic graph. A resident scope cannot import an authoring descriptor graph. ScriptType.dll remains independent of SMA; only the compiler-side adapter consumes AST evidence. Structural contracts can be erased at build time or retained as typed descriptors with revocable role bindings.
- **Evidence:** differential tests, structural lint, Guard, non-loading binary queries and coverage. An observed call is not a universal binding proof; an ABI check is not a proof of arithmetic equivalence.

## Trust and security

PSC authoring requires a trusted PowerShell session with the required language capabilities. It uses reflection, metadata readers, assembly emission and native interop openly. Do not bypass AMSI, Defender, App Control or execution policies. Follow local signing and deployment policy. Only compile or execute trusted source; conformance runs candidate code and is not a sandbox. Use trusted assemblies for CIL import/compilation and trusted data for `FixedParametersPath` and `ProfilePath`. Query is the non-loading metadata inquiry path for supported binaries. Determinism and SHA-256 identify artifacts; they do not establish publisher trust or safety.

Microsoft guidance: [script injection](https://learn.microsoft.com/en-us/powershell/scripting/security/preventing-script-injection), [PowerShell security](https://learn.microsoft.com/en-us/powershell/scripting/security/security-features), [unsafe deserialization](https://learn.microsoft.com/en-us/dotnet/standard/serialization/binaryformatter-security-guide).

## Vocabulary and change control

PSC uses established configuration-management and software-assurance terminology where it fits. The following is a project vocabulary, not a claim of NIST compliance. References: [NIST SP 800-128](https://csrc.nist.gov/glossary/term/baseline_configuration), [NIST SP 800-218 (SSDF 1.1)](https://csrc.nist.gov/pubs/sp/800/218/final), and the [NIST CSRC glossary](https://csrc.nist.gov/glossary).

| Term | Meaning in PSC |
|---|---|
| Canonical source | The authoritative maintained PSC source, not a projection or compiled artifact. |
| Baseline | An approved revision with known identity; Git HEAD is a comparison point, not inherently approval. |
| Candidate | A proposed new canonical source or artifact, not yet accepted. |
| Configuration item | An independently controlled source, toolchain, policy or release artifact. A projected unit need not be a separate configuration item. |
| Drift | An unintended discrepancy from a specified baseline, requirement or documented contract. An intentional proposed change is not inherently drift. |
| Manifest | Ordered inventory and identities of projected units; not an approval or signature. |
| Provenance | Origin and transformation history of an artifact or observation. |
| Integrity verification | Compare bytes or a digest against an independently trusted expected value; not publisher authentication. |
| Finding | A diagnostic against a stated criterion, not necessarily a vulnerability. |
| Verification | Objective evidence that specified requirements are met. |
| Validation | Evidence of fitness for a specific intended use and operating environment. |
| Conformance | Assessment against declared criteria and explicit scope; not a security certification. |
| Assurance | Justified confidence supported by evidence, not a synonym for a passing test. |
| Coverage | What was examined or exercised, with omissions and unresolved cases distinguished. |

PSC-specific terms retain their distinct meanings:

| Term | Meaning in PSC |
|---|---|
| UnCollate / Collate | Project canonical source into ordered, editable units / validate and reconstruct a single-file candidate. |
| Consolidate | Follow admitted source-inclusion relationships to form a single script; not the inverse of UnCollate. |
| Faculty | Named, independently realizable runtime/compiler capability with declared dependencies. |
| Realization | An executable representation of admitted source, such as a managed assembly or native image. |
| Referent | The structural entity identified by a reference; for an AST match, the Target is its referent. |
| Reference | A typed source- or artifact-bound reference to a referent, including identity and extent. It does not establish arbitrary runtime binding. |
| Result | A typed record of an operation's outcome, scope and relevant evidence; not approval or an independently signed attestation. |
| Guard | Candidate admission policy against a committed comparison source and protected checker. |
| Conform | Orchestrate scoped verification and record its results; acceptance and promotion remain explicit decisions. |
| Appliance | A one-shot executable unit in source form (.sexe). |
| Observation | A recorded result of examining or executing against a referent under stated conditions; not a general conclusion. |
| Percept | A retained, typed recognition of a relationship, grounded in observations with explicit scope and validity; distinct from an executable capability or authority. |
| Proposal | A candidate explanation, change, or operation to assess; Propose does not establish correctness. |
| Prediction | An expected observation derived from a proposal before assessment of its outcome. |
| Assessment | Evaluation of evidence against declared criteria; distinct from admission. |
| Admission | An explicit decision under a stated policy and authority; not a consequence of discovery alone. |

Use these terms consistently in code, help, results and development discussion. Keep source identity, assessment criteria, observation, outcome and authorization distinct. A successful partial assessment must not be described as complete; an unknown must not be described as absent. Preserve established PSC operation names unless their semantics change.

## Integration roadmap

PSC is the upstream compiler, SDK, semantic development environment and procedural learning substrate for the related repositories. The maintained implementation is PSC.ps1; source projections, compiled faculties, packages and this README are derived representations. Applications retain application-specific state, models, tests and policies. The campaign is a dependency graph, not a linear migration or a mandate to copy every donor. This roadmap supersedes the November 8 roadmap and reconciles the [November 11 campaign](https://github.com/MansfieldPlumbing/Pwsh-Development/blob/403f11a34e56dc2a1f3354d6501c5ab19344be1e/docs/psc-plan/PSC-The-Plan.md). Historical measurements remain at their original revisions.

### Baseline and objective register

Assessment basis: PSC [c7ef1f5](https://github.com/MansfieldPlumbing/PSC/commit/c7ef1f5420244d80227f32ad6ce9cf3dc4a52442), reviewed November 25, 2026. Existing implementation is not equivalent to completed acceptance. At this baseline seven faculties, ordered projection, typed query, revision-bound replacement/undo, retained semantic source identity, candidate Guard including embedded source, managed compilation, NativeAOT/COFF and direct x64 ELF leaf emission exist. Development Conform reported 542 passing fixture assertions across ten executed stages; historical Windows Verify was explicitly skipped. Full candidate-independent conformance is not established.

States: Existing = demonstrated mechanism requiring remaining scope checks; Planned = a defined objective; Research = evidence needed before committing to a design; Accepted = explicitly accepted with revision, evidence, scope, omissions and redundancy disposition. Outstanding prerequisites are computed from the typed register, not hand-maintained readiness labels. They gate acceptance, not all incremental development. An objective is never accepted merely because declarations exist or a conformance stage passes.

```powershell
$api.Roadmap()                 # Typed objective declarations
$api.AssessRoadmap()           # Live structural witnesses and outstanding prerequisites
$api.AssessRoadmap($result)    # Add a Conform report for this exact source revision
```

The structural checks reuse the source-query visitor over the API AST and the faculty inventory. ObservedDeclarations carries source-bound PscMatch references, including faculty declarations; ObservedFaculties carries PscFacultyUnit records. Conformance stages are observations only; the report retains its original scope. Without a report, ConformanceReported is false; an unexecuted stage is NotRun, not Passed. Assessment does not promote a candidate or confer authority; acceptance records must be reviewed against independently controlled criteria. The register rejects duplicate IDs, missing or repeated dependencies, cycles, missing declared witnesses and incomplete acceptance records. ### Acquisition, integration and publication procedure

1. Establish the requirement and accepted revision; query PSC first for equivalent types, operations and dependencies. Search donor source, tests, history and documentation, including abandoned approaches and contradictory evidence. Pin repository, commit, blob, extent, license and independent test inputs. Record what is already implemented, missing, refused or unknown. Avoid importing obsolete wrappers, parallel binders, stores, dispatchers or orchestration layers.
2. Extract the mechanism, not the donor architecture. Reconcile identity, semantics, authority, lifetime, failure, units and numeric representation with existing PSC types. Prefer NIST configuration/assessment/measurement vocabulary, ECMA-335 and ISA terminology in their domains; retain Percept, Referent, Faculty and other precise PSC concepts. Use Propose/Proposal and Investigation; do not introduce donor Hunt terminology. Preserve original names in provenance. Decide whether to extend an existing faculty or introduce a new one by measured dependency/realization needs, not donor file boundaries.
3. Derive executable acceptance criteria before implementation; preserve independent baseline fixtures and record expected outcomes. First reproduce the donor, then establish equivalence or explicitly document intentional differences. Use typed SMA declarations, AST queries and existing edit/Collate machinery; do not author C#, regex-parse source, hide code in scriptblocks, use JSON as an object graph, or add untyped records. A necessary lowering extension gets its own minimal repro and full application test. Canonical source, tests, comments, guide and roadmap change together; no alternate maintained implementation tree.
4. Verify at the lowest meaningful boundary and across the complete affected path: parse/type/bind, positive and negative unit cases, independent differential oracle, deliberate perturbation, format/decode/ABI tests, full application source compile and execution, projection/assembly round trips and Guard/Conform. Fuzz bounded parsers/encoders and exercise limits, resource cleanup, error and concurrency paths as appropriate. Affected is advisory, not permission to omit regression stages. Candidate tests supplement protected baseline tests; neither a passing candidate-owned test nor a matching hash proves authorization or semantic correctness. Trusted source only; conformance is not a sandbox.
5. Measure on identical pinned workloads and conditions: cold/warm elapsed and CPU/device time, peak/retained memory, artifact size, dependencies and throughput; include repetitions, distribution, hardware/runtime, workload, precision, coverage and tolerances. Separate authoring cost, realization cost, execution and transport; test held-out inputs and scalar/portable references. Optimize demonstrated bottlenecks; preserve exactness where required, otherwise establish acceptable error before changes. Report failures and regressions, not just best runs. For procedural learning compare cold investigation, retained observations and retained capabilities on unfamiliar cases; measure acquisition and reuse costs, false acceptance and invalidation. Multiple independent observations are required where possible; statistical thresholds require justified distributions, not a universal three-sigma rule.
6. Publish a small cohesive candidate after review. Record parent, source/artifact identities, test commands/results, coverage, omissions, measurements and rollback path. Run the full available conformance scope; label unavailable platforms or tools and incomplete checks explicitly. A change to protected assessment authority requires separate explicit approval and old/new comparison, never self-admission. A verified development checkpoint can advance main with incomplete platform verification explicitly disclosed; no release-quality claim until the relevant full scope passes. Use a compare-and-swap/fast-forward main update, never force past another change, and verify remote HEAD and content. Keep main usable; commit each independently verified increment, not one end-of-campaign bulk import. On failure retain the last accepted artifact and diagnose before retry.
7. Regenerate README from PSC.ps1 with Readme mode, compare exactly, keep examples/API names and progress current, and update source comments where contracts or provenance changed. Do not manually maintain a second roadmap. Donor README updates distinguish reported historical results from current tests, link concrete evidence and the upstream objective, correct stale names/commands and describe remaining work. Avoid gratuitous edits and unsupported marketing. Rebuild downstream against pinned PSC after acquisition; verify equivalence/performance before removing redundant implementations. Record unresolved defects and what remains downstream.

## Live reference

```powershell
$api.AssertSurface()
$api.Modes
$api.Parameters
$api.Measures() # Demand-driven measurements of the acquired source revision
$api.Functions
$api.Classes
$api | Get-Member
& ./PSC.ps1 -Mode Capability
```

The API retains the acquired source revision. LowerDeclarations(names) compiles an explicitly selected set of top-level classes and enums, including those in PSC's begin block; LowerDeclarations(ast,names) accepts a donor source AST, including the original body of a named declaration scope when the selection is contained in that body. It compiles the selected original declarations directly, retaining their parser-owned AST identities without synthesizing or executing an enclosing script. Include required source types in the selection; program compilation is a separate operation. Managed declaration lowering supports one selected source-owned base class, including forward references, inherited fields and virtual methods, and parameterless base construction. External base classes, interfaces, explicit base arguments and MethodNames selection with inheritance remain unsupported. Eligible queries reuse its AST after byte-identity verification; declaration queries share the roadmap declaration inventory and use an ordinal-ignore-case name index. IndexedArtifacts counts indexed source artifacts; SitesExamined counts candidate declarations actually tested, and VisitorCallbacks counts visits in the query itself. Pull windows advance through retained declaration sites without replay; other source kinds still traverse the AST. Measurements are acquired only on the first Measures() call. ReadSource(path) still acquires all measurements. The API is derived from the running script, so mode names and parameter evidence do not depend on a previous session's notes. Use `Describe(mode)` for dispatcher extents and associated definitions. CLI inventory below is generated; source hash, local paths, runtime and measurement values are available from the live API rather than frozen into the README. Regenerate with `& ./PSC.ps1 -Mode Readme`.
